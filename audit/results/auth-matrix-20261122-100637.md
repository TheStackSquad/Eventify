## Next steps (where to look)

- **AUTH-S3 [FAIL]** the lockout clock has a time zone: F403: login_attempts.last_attempt_at has no time zone, and the code writes the server local time. IsAccountLocked compares it with UTC, so a server in Lagos time keeps accounts locked about an hour longer than 10 minutes. Migrate the column to timestamptz and write UTC.
- **AUTH-A3 [FAIL]** a sign-up cannot choose its own user id: F417: the sign-up body binds straight into models.User, so id (and other fields) can be set by the caller. Bind into a request struct with only name, email and password.
- **AUTH-A4 [FAIL]** the same email twice is refused cleanly: F412: CreateUser turns every database error into "already exists" and the handler answers 500. Detect the unique violation (SQLSTATE 23505) and answer 409; report real errors as 500.
- **AUTH-A5 [FAIL]** the same email in another letter case is the same account: F416: emails are not normalised. Trim and lower-case them on sign-up, login and reset, and add a unique index on lower(email).
- **AUTH-A7 [FAIL]** a password longer than bcrypt can use is refused: F418: bcrypt uses at most 72 bytes. Refuse longer passwords with 400 (or pre-hash them); a 500 or a silently truncated password are both wrong.
- **AUTH-L3 [FAIL]** failed logins for emails that do not exist leave no record: F419: Login records a failed attempt even when the email does not exist, so anyone can fill login_attempts. Record attempts only for existing accounts, or throttle by IP.
- **AUTH-T5 [FAIL]** logging out with a Bearer token revokes it: F408: Logout reads the tokens from cookies only. A client that authenticates with a Bearer header is never revoked. Read the Authorization header as well.
- **AUTH-E1 [FAIL]** /health does not describe the rate-limit settings: F413: /health tells anyone whether localhost is exempt from rate limits. Return status only.
- **AUTH-C2 [INFO]** the Secure flag on the session cookies: F414: Secure depends on COOKIE_SECURE (default off). Production must set it, and logout must clear cookies with the same flags.

## Claims supported by this run

- A sign-up cannot choose its own role, and invalid sign-ups are rejected.
- Login answers never expose secrets, and a wrong password and an unknown email look the same.
- Session cookies are HttpOnly with SameSite, and state-changing requests need a matching CSRF token.
- Forged, unsigned and re-signed tokens are refused.
- Refresh rotates both tokens and needs a session.
- Only the named website origin receives CORS permission.

## Not demonstrated in this run

- A sign-up cannot choose its own user id. (needs: AUTH-A3)
- A duplicate email is refused cleanly, in any letter case. (needs: AUTH-A4, AUTH-A5)
- Logout kills the access and the refresh token, whichever way the client authenticated. (needs: AUTH-T5)

## Limits of this evidence

- One backend process on one machine. Multi-instance behaviour is not exercised.
- Paystack test mode and one payment channel. Live mode and other channels may behave differently.
- The webhook URL saved in the Paystack dashboard cannot be read by this script; T1.2 confirms it indirectly.
- This run uses a local backend and the rig database; no tunnel is used.
- Rate limiting is not exercised: the limiter skips localhost, so those checks need rig mode (a later piece).
- Lockout, token expiry, session lifetime and the password-reset flow are covered by later pieces.
