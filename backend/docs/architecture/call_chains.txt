┌───────────────────────────────────────────────────────────────────────────┐
│ CHAIN 5: Subscription Status Change → Vendor Tier Sync (Trigger)          │
└───────────────────────────────────────────────────────────────────────────┘

Triggered by: Subscription status change (payment webhook, expiry worker, etc.)

  ┌─ Database Event: INSERT/UPDATE on subscriptions table
  │
  ├─ Trigger: trigger_sync_vendor_tier
  │  │  Type: AFTER INSERT OR UPDATE
  │  │  For Each Row
  │  │
  │  └─ Execute Function: sync_vendor_subscription_tier()
  │
  ├─ Function Logic:
  │  │
  │  ├─ IF NEW.status = 'active' AND not expired
  │  │  │
  │  │  └─ UPDATE vendors
  │  │       SET subscription_tier = NEW.tier,
  │  │           updated_at = NOW()
  │  │       WHERE id = NEW.vendor_id
  │  │
  │  └─ ELSIF NEW.status IN ('expired', 'cancelled') OR expired
  │     │
  │     ├─ Check for other active subscriptions:
  │     │    SELECT 1 FROM subscriptions
  │     │    WHERE vendor_id = NEW.vendor_id
  │     │      AND status = 'active'
  │     │      AND (expires_at IS NULL OR expires_at > NOW())
  │     │      AND id != NEW.id
  │     │
  │     └─ IF no active subs found:
  │        └─ UPDATE vendors
  │             SET subscription_tier = 'free',
  │                 updated_at = NOW()
  │             WHERE id = NEW.vendor_id
  │
  └─ Cascading Effects:
     ├─ Analytics tier gating (immediate)
     ├─ Search result ordering (on next query)
     └─ Leaderboard eligibility (on next refresh)

Database Impact:
  ├─ Automatic: No application code needed
  ├─ Consistency: Always synced (ACID guarantee)
  └─ Performance: ~1-2ms per subscription change
